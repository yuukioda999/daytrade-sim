# ADR-0007: 自動の練習売買を動かす仕組み

- 状態: 承認済み(2026-11-17)
- 日付: 2026-11-17

## 背景

自動の練習売買は、取引時間中に定期的に足データを取り、条件を判定し、売買を記録する処理を回し続ける必要がある。米国市場の取引時間は日本時間の深夜から早朝にあたる。画面を開いていなくても動いてほしい。

## 選択肢と評価

| 案 | 評価 |
|---|---|
| A: ブラウザで動かす | 画面を開いている間だけ動く。タブを閉じるか、スリープすると止まる。蓄積に穴が開く |
| B: Next.js のサーバーの中で定期実行する | プロセスが1つで済む。開発サーバーの再読み込みで処理が二重に起動する危険がある。Web の不具合で蓄積も止まる |
| C: 別のプロセス(ワーカー)として動かす | Web を止めても蓄積が続く。処理を単体で起動してテストできる。起動するものが2つになる |

## 決定

C。`npm run worker` で起動する Node.js のプロセスを用意する。Web と同じ domain、application、infrastructure の層を使い、同じ SQLite に書く。

## 理由

- 蓄積の継続が第1弾の目的なので、画面の状態に左右されない形にする
- ワーカーは「時計、市場カレンダー、データ取得元、保存先」を受け取って1回分の処理を行う関数の繰り返しにできる。過去データで試す機能は、同じ関数に過去の時計とデータを渡すだけで実現できる

## 影響

- 利用者は取引時間中、Mac を起こしたままワーカーを動かす必要がある。スリープすると止まる。README に手順と、スリープを防ぐ方法を書く
- 止まっていた時間のデータは、次に起動した時に Alpaca から取り直して埋める。ただし止まっていた間の練習売買をあとから計算し直すかどうかは spec で決める
- 同じ足を2回処理しても記録が重複しないようにする(冪等性)
- 画面に「最後にデータを受け取った時刻」と、ワーカーが動いているかどうかを出す

## 決め直す条件

- Mac を取引時間中に起こしておく運用が続かない場合は、安価なサーバーで動かす案を含めて決め直す。その時は「ローカルで動かす」前提と秘密の置き場所も見直す
