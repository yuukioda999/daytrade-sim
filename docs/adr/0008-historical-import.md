# ADR-0008: 過去データの取得をどこで動かすか

- 状態: 承認済み(2026-11-20、人間が推奨の B を採用)
- 日付: 2026-11-20

## 背景

SPEC-006 の AC-006-09 から 11 で、設定の画面から期間(最大1年)を選び、Alpaca から4銘柄(SOXL、TQQQ、TSLL、NVDL)の5分足を取って保存する。進み具合を出し、途中で失敗してもそれまでの分は残し、失敗した期間を出して取り直せるようにする。

量の見込み(計算。実際には取っていない): 1日の通常の取引時間の5分足は78本。1年の取引日は約250日なので、1銘柄で約2万本、4銘柄で約8万本。Alpaca の1回の応答は最大1万本(公式の資料)で、無料の上限は毎分200回。1銘柄の1か月分(約1,600本)を1回で取れば、1年分は約48回になる。1回に数百ミリ秒から数秒かかるとすると、全部で数十秒から数分の見込み。

ADR-0007 で、自動売買はワーカー(別のプロセス)で動かすと決めた。ワーカーは T9 で作るので、T8 の時点ではまだない。

## 選択肢と評価

| 案 | 評価 |
|---|---|
| A: 画面のサーバー(Next.js)の中で、裏の処理として動かす。画面は進み具合を定期的に問い合わせる | 画面を閉じても続く。進み具合を覚えておく仕組みが要る。開発サーバーの読み直しで処理が途中で消える、または二重に動く危険がある(ADR-0007 で B を選ばなかった理由と同じ) |
| B: 画面が「1銘柄の1か月分」ずつサーバーに頼み、全部が終わるまで順に頼み続ける。取り終えた範囲は DB に記録する | 1回の頼みは数秒で終わり、サーバーに長く動く処理を持たない。進み具合は画面が数えるだけで済む。途中で失敗した範囲は画面が分かる。画面を閉じると止まるが、もう一度始めると取り終えた範囲を飛ばして続きから取れる |
| C: ワーカー(T9)に頼む | 画面と関係なく動く。T9 ができるまで使えない。画面とワーカーの間で、頼みと進み具合をやりとりする仕組み(DB の表など)が要る |

## 決定

B(人間が 2026-11-20 に推奨を採用)。

## 理由

- 長く動く処理をサーバーに持たないので、開発サーバーの読み直しや二重起動の心配がない
- AC-006-11(失敗してもそれまでの分を残し、取り直せる)を、取り終えた範囲の記録だけで満たせる
- 量は数十秒から数分の見込みで、画面を開いたまま待てる長さ
- T8 の時点で動く。ワーカー(T9)に頼らない

## 影響

- 取り終えた範囲を「銘柄と取引日」の単位で DB に記録する。同じ足を二重に保存しない(AC-006-10)
- 画面を閉じると取得が止まることを、画面に書く
- 通常の取引時間(米国東部 9:30 から終了まで)の足だけを保存する。時間外の足は捨てる
- 取得は「今日より前の日」だけにする。今日の足はワーカー(T9)がためる

## 確認したこと、していないこと

- 確認した(2026-11-20、Alpaca の公式の資料): 足の取得の入口は `https://data.alpaca.markets/v2/stocks/bars`。1回の応答は最大1万本で、続きは next_page_token で取る。無料のプランで全市場(SIP)のデータを取るには、終わりの時刻が15分以上前である必要がある。latest の入口は SIP では有料
- 確認していない: 実際の応答の速さ、日本からの通信の速さ、足ごとの出来高加重平均価格(vw)が必ず付くか
