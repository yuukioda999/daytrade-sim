# ADR-0010: 過去データで試す処理の作り方と見せ方

- 状態: 承認済み(2026-11-20、人間が決めること 1、2 とも推奨の A を採用)
- 日付: 2026-11-20

## 背景

T11 で「過去データで試す」(SPEC-006 AC-006-12、SPEC-004 AC-004-04、SPEC-007 AC-007-18)を作る。spec が決めているのは次のことだけで、どこで始めるか、どの日を試すか、お金をどう引き継ぐか、どう見せるかは決まっていない。

- SPEC-002 と SPEC-003 のルールで試し、結果を毎日ためた記録とは別に保存する(AC-006-12)
- 成績の画面で、毎日ためた記録と混ぜずに別の欄に出す(AC-004-04)
- 「過去データで試す」に切り替えると、試している日付を大きく出し、今日の市場の表示と取り違えないようにする(AC-007-18)

計算は、T9 の replayDay(その日の足を最初から順に処理する純粋関数、ADR-0009)をそのまま使える(ADR-0004、ADR-0007 の狙い)。過去データは T8 で設定の画面から取り込める(ADR-0008)。

## 決めること 1: どこで始め、どう見せるか

| 案 | 評価 |
|---|---|
| A: 設定の画面の「過去データ」の欄に「過去データで試す」のボタンを置く。押すと、取り込んだ期間の全部の日を古い順に試し、結果を別の表に保存する(前の結果は置き換える)。成績の画面の「過去データで試した結果」の欄に、まとめと日ごとの表を出す。ダッシュボードの上に「今日の市場 / 過去データで試す」の切り替えを置き、「過去データで試す」では、試した日を1日選んで、その日のチャートと売買を出す(日付を大きく出す) | spec の3つの受け入れ基準をすべて満たす。ワイヤーフレーム(ヘッダーの切り替え、成績の画面の欄)に合う。画面の部品(T10 のダッシュボード)を使い回せる。作る量は一番多い |
| B: A のうち、ダッシュボードの切り替えを作らない。結果は成績の画面にだけ出す | 作る量は少ない。AC-007-18 を満たさないので、spec から外す変更が要る |
| C: 期間を選んで試す(設定の画面で開始日と終了日を選ぶ) | 試す範囲を絞れる。A の「全部の日」と比べて入力と確かめの作業が増える。取り込んだ期間を選べば同じことができるので、効果は小さい |

推奨: A

## 決めること 2: お金の引き継ぎと、試す日の条件

| 案 | 評価 |
|---|---|
| A: 試し始める時の設定の元手と為替で始め、損益を次の日に引き継ぐ(SPEC-003 の残高と同じ)。自動売買は毎日 ON とみなす。4銘柄すべての足を取り終えた日だけを試す。取引量の基準は、その日より前の取り終えた20取引日。「あとから処理」の印は付けない | 毎日ためた記録と同じルールで比べられる。過去の日の設定の履歴は使わない(試す時の条件を1つにして、結果を読みやすくするため) |
| B: 日ごとに元手を初めの値に戻す(引き継がない) | 日ごとの比べやすさは上がるが、SPEC-003 の残高の考え方と違い、成績の画面の残高の列と合わない |

推奨: A

## 決定

決めること 1、2 とも A(人間が 2026-11-20 に推奨を採用)。

## 影響

- 保存先に、過去データで試した結果の表(試した日、記録、試した時の元手と為替)を足す。毎日ためた記録(trades)とは分ける(T9 のレビュー 11)
- 試す処理は画面のサーバーで動く(通信しない。保存した足だけを使う)。1年分(約250日 × 4銘柄)でも計算は数秒の見込み(測っていない)

## 確認したこと、していないこと

- 確認した: SPEC-004、SPEC-006、SPEC-007 の該当の受け入れ基準、ワイヤーフレームの成績の画面とヘッダー(2026-11-20)
- 確認していない: 1年分を試す時間(実装のあとに測る)
