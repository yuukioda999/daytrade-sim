# ADR-0006: 秘密情報の扱い

- 状態: 承認済み(2026-11-17)
- 日付: 2026-11-17

## 背景

第1弾で扱う秘密は、Alpaca の接続用キー(キー ID とシークレット)。実運用の段階で Discord の Webhook の URL が加わる。リポジトリは GitHub で公開する。

## 選択肢と評価

| 案 | 評価 |
|---|---|
| A: `.env.local` だけ | 最も単純。画面から設定できない |
| B: 画面で入力し、サーバー側の SQLite に保存する | 画面から設定できる。ブラウザに残らない。DB ファイルの中は平文 |
| C: ローカルストレージ | 開発者ツールと通信履歴にそのまま出る |

## 決定

B。あわせて次を守る。

- 画面には「設定済みかどうか」と末尾の数文字だけを返す。全文を返す API を作らない
- キーをログ、エラー文、テストのスナップショットに出さない
- DB ファイルを置く `data/` は `.gitignore` で除外する。`.env.example` にはダミー値だけを書く
- 外部への通信先はコードの中で固定する(Alpaca のデータ API のホストだけ)。利用者が入力した URL へ通信しない
- CI に秘密の混入検査を入れる

## 理由

- 公開リポジトリなので、コミットに秘密が入らない仕組みを先に作る
- 通信先を固定すれば、キーが意図しない宛先に送られることがない

## 影響

- DB ファイルを他人に渡すとキーも渡る。README に明記する
- 保存時の暗号化は行わない。同じ Mac の中に復号の鍵も置くことになり、守れる範囲が増えないため。必要になったら OS のキーチェーンを使う案で決め直す
- キーに触れる変更は security-reviewer のレビュー対象にする

## 実運用の段階で決め直すこと

- Discord の Webhook の URL も同じ方針で保存する。その時は通信先に Discord の Webhook のホストとパスの形式だけを追加で許可する
