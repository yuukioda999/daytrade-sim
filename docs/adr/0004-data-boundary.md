# ADR-0004: データ取得の境界

- 状態: 承認済み(2026-11-17)
- 日付: 2026-11-17

## 背景

市場データの取得元は、今日の市場(Alpaca)、過去データ、テスト用の固定データの3つがある。あとから別の提供元や Python の処理に差し替えられるようにしたい。時刻の判定(米国東部時間、夏時間、休場日)もテストで再現できる必要がある。

## 選択肢と評価

| 案 | 評価 |
|---|---|
| A: ブラウザ内のインタフェース | 単純。接続用キーがブラウザに出る。ブラウザを閉じると蓄積が止まる |
| B: サーバー側のポートとアダプタ。画面は自前の API だけを見る | 差し替えがサーバー側で閉じる。キーがブラウザに出ない |
| C: 最初から別のデータサーバーを立てる | 第1弾には過剰 |

## 決定

B。次のインタフェースを置く。

| インタフェース | 役割 | 実装 |
|---|---|---|
| MarketDataSource | 銘柄と期間を指定して足データを返す | Alpaca、保存済みデータの再生、テスト用の固定データ |
| Clock | 現在時刻を返す | 実時計、テスト用の固定時計 |
| MarketCalendar | ある時刻に市場が開いているか、取引開始と終了の時刻を返す | 休場日と短縮取引日の表を持つ実装 |
| 各 Repository | 足データ、練習売買、設定の読み書き | SQLite、インメモリ |

## 理由

- 条件の判定と売買のルールは、足データと時刻を引数に受け取る純粋関数にできる。手計算との比較テストが書きやすい
- 「今日の市場」と「過去データで試す」は、MarketDataSource と Clock の実装を差し替えるだけで同じルールを通せる
- 夏時間と冬時間、休場日のテストが実時刻に依存しない

## 影響

- 画面は Route Handler を通して読む。更新の届け方(定期的な取得か、SSE か)は spec で決める。データが15分遅れで1分単位なので、定期的な取得で足りる見込み(未確認)
- 休場日と短縮取引日の表は年ごとに更新が要る。対象年の範囲と更新方法を README に書く
- 過去データで試した結果と、毎日ためた結果は、別々に保存して混ぜない
