# ADR-0003: データの保存先

- 状態: 承認済み(2026-11-17)
- 日付: 2026-11-17

## 背景

保存するものは次のとおり。

- 株価の足データ(毎日ためる分と、過去データ)
- 練習売買の記録、日ごとの成績
- 設定(元手、為替レート、自動売買の ON/OFF、1回の買いに使う金額)
- 市場データの接続用キー(秘密。ADR-0006)
- 画面の状態(シミュレーターのスライダー位置など)

## 選択肢と評価

| 案 | 評価 |
|---|---|
| A: ローカルストレージだけ | サーバー側から読めない。接続用キーをブラウザに置くことになる。足データをためるには容量が足りない。自動売買はブラウザを開いていないと動かせない |
| B: SQLite だけ | すべてサーバー側で扱える。画面状態の保存にも API の往復が要る |
| C: 併用 | 足データ、売買の記録、設定、キーは SQLite。画面の状態だけローカルストレージ |

## 決定

C。SQLite のファイルはリポジトリ内の `data/` に置き、`.gitignore` で除外する。

## 理由

- 自動売買と足データの蓄積はサーバー側で動くので、サーバー側から読み書きできる保存先が要る
- 秘密をブラウザに置かずに済む
- 画面の状態は消えても困らず、サーバーに持つ理由がない

## 影響

- 保存はすべて Repository のインタフェース越しに行う。テストではインメモリ実装に差し替える
- 自動売買のプロセスと Web のプロセスが同じ SQLite を使う(ADR-0007)。WAL モードを有効にする
- DB ファイルを消すと、ためたデータと成績が消える。README にバックアップの方法を書く

## SQLite の使い方

A に決定(2026-11-17 に確認済み)。

| 案 | 評価 |
|---|---|
| A: better-sqlite3 と Drizzle ORM | スキーマを TypeScript で書け、型がクエリまで通る。マイグレーションをファイルで管理できる。ネイティブモジュールのビルドが要る |
| B: Prisma | 道具がそろっている。生成物と実行時の仕組みが大きく、この規模には重い |
| C: better-sqlite3 だけ(SQL を直接書く) | 依存が最小。型は自分で合わせる必要があり、型安全性を見せる目的に合わない |
| D: Node.js 標準の node:sqlite | 追加の依存なし。安定版かどうかを確認していない |

## 確認していないこと

- better-sqlite3、Drizzle ORM の最新版と、Next.js の現行版との組み合わせでの動作
- node:sqlite の安定度
