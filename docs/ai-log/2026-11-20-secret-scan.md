# AI ログ: 秘密の混入検査を CI に入れる

- 日付: 2026-11-20
- 関連: ADR-0006、T7 のセキュリティレビュー 5、docs/plan/phase1-plan.md の T8
- 使った AI: Claude(claude-opus-5-5)

## 指示

PR #7 のマージのあと、人間が「GitHub の secret scanning と push protection を AI が gh で有効にする」(推奨)を選んだ。あわせて、本物のキーで通信を始める T8 の前に、CI に gitleaks を入れる。

## 出力

- CI に `secret-scan` のジョブを足した。gitleaks v8.30.1 の公式のコンテナで、リポジトリの全履歴を調べる。見つかった値はログに出さない(`--redact`)
- `.gitleaks.toml`: gitleaks の標準の規則を使い、テストのダミーのキー(PKTESTKEY000…、TestSecret000… など)だけを除外する
- SPEC-006 の決めたこと5(まだ保存していない時の値)を、人間が確認したと書いた(2026-11-20)

## GitHub の secret scanning を有効にできなかったこと

- `gh api -X PATCH` でリポジトリの設定を変えようとしたが、AI の作業環境からはリポジトリの設定の書き込みが許されていなかった(HTTP 403)
- その時に、リポジトリが **非公開(private)** だと分かった。人間に「公開リポジトリは無料」と説明していたが、確かめていなかった。非公開のリポジトリで secret scanning を使うには、有料の機能(GitHub Advanced Security)が要る見込み(確かめていない)
- 人間に伝え、公開する時に有効にするかを決めてもらう

## 版の決め方

- gitleaks の最新の安定版は v8.30.1(2026年3月)と、複数の資料で確かめた。作者は「機能は完成していて、今後は安全上の修正だけ」としている
- gitleaks-action は Node 20 で動く版があり、GitHub の実行環境から Node 20 が外される予定がある。依存を増やさないよう、公式のコンテナを版のタグと中身のハッシュ(digest)で固定して使った。digest は、最初の CI の実行でコンテナを取ってきた時のログ(Digest: sha256:c00b6bd0…)から取った。最初に取ってきた中身を正しいものとして固定する形で、gitleaks の作者が公開している値と見比べてはいない

## 確かめたこと

- AI の作業環境では gitleaks もコンテナも動かせないので、この PR の CI で確かめた。ログに「28 commits scanned」「no leaks found」と出た(全履歴を調べ、ダミーのキーを除外したうえで漏れは0件)
- テストのダミーのキーを除外する正規表現が、リポジトリにあるダミーのキー6種類(src と e2e)に当たることを、grep で一覧を作って見比べた

## AI が間違えた点と学び

| 間違えた点 | どう分かったか | 次からどうするか |
|---|---|---|
| リポジトリを公開だと思い込み、「公開リポジトリは無料」と人間に説明した | 設定を変える API の応答と、リポジトリの情報を見た時 | 料金や条件に関わる説明の前に、リポジトリの公開・非公開などの前提を確かめる |

## 確かめていないこと

- gitleaks が本物のキーの形(Alpaca のキー)を見つけられるか。標準の規則に Alpaca 用の規則があるかは見ていない
