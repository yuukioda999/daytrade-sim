## 確かめたこと(証拠)

- 単体テスト、型チェック、lint が成功(AI の作業環境)
- SPEC-005 の例2は「表計算ソフトで求めた値と比べる」となっているが、AI の作業環境に表計算ソフトがない。代わりに Python の Decimal(有効桁 50)で、同じ定義を JavaScript とは別に計算した値と比べた。例2は 20,522.2004... で、小数2桁まで一致した。既定値の3つの条件の年次の値(税金、運用中、貯金、合計)も同じ方法で求めて比べた
- わざと壊して、テストが落ちることを確かめた。最初の8通りのうち2通りで通ってしまった(年の利益がマイナスの時の税金、米国東部時間の日付でまとめる処理)。どちらもテストの値がその分岐を通っていなかった。テストを足し、同じ壊し方で失敗することを確かめた

## レビュー(reviewer)と対応

reviewer の指摘は8件(高 0、中 2、低 6)。計算の誤りはなく、reviewer が Python の Decimal(有効桁 60)で組み直した計算とも、すべての値が一致した。spec を変えずに直せるものは、人間の指示(2026-11-19)により AI が推奨どおりに直した。

| 番号 | 指摘(要点) | 対応 |
|---|---|---|
| 1 | 3つの条件の比べのテストが税金 ON だけで、「お試しなし」の税金を常に ON にしても通る | 税金 OFF で3つの条件を比べるテストを足した(参照の値は Decimal で計算) |
| 2 | 売買がなかった取引日が日ごとの結果に入らず、0円の日が数えられない | 人間が推奨を採用(2026-11-20)。自動売買が動いていた取引日は売買がなくても行を作ると SPEC-004 に書いた。行を作る処理は T9、T11 |
| 3 | プラス、マイナス、0円の区分は内部の値で決めるので、+0.3円の日は「プラス」なのに画面は 0円 | 人間が推奨を採用(2026-11-20)。四捨五入する前の値で決めると SPEC-004 に書いた。表に小さく出すかは T11 で決める |
| 4 | 貯金 100% を simulateScenario で試すテストがない | 足した |
| 5 | 表の並べ替え、元手 0 のエラー、損失の上限の日を 0 で足す行が、テストで守られていない | 0 で足す行は消した(上限は売り終わった分で決まるので使われない)。ほかの2つはテストを足した |
| 6 | スライダーで刻みを足し算で積み上げると、上限の値でエラーになる | T6 で刻みの数から値を作ると plan に書いた |
| 7 | 単体テストの名前に、画面の基準の AC-005-04 が入っている | 外した |
| 8 | 例2は表計算ソフトではなく Decimal と比べている | spec は変えない。人間が表計算ソフトで確かめるかは任意 |

壊して確かめたこと: reviewer がすり抜けたと報告した壊し方のうち、コードに残っている4通りを試し、すべてテストが失敗することを確かめた。
