## shadcn の部品の cn について

人間が `npx shadcn@latest add` で部品を足したところ、部品が `cn`(クラス名をつなぐ関数)を npm の `cn` パッケージから読む形になり、`cn` パッケージが依存に入った。

- 最初、人間に「無関係なパッケージ」と伝えたが、中身を確かめると shadcn の作者が出している公式のパッケージ(clsx と tailwind-merge の代わり)だった。言い方を訂正する
- shadcn 4.23 の中身を読むと、部品を足す時に clsx と tailwind-merge を `cn` パッケージに書き換える処理があった。components.json の設定で止める方法は見つけられなかった
- 2つの cn のどちらにそろえるかを人間に聞き、自分の `@/components/ui/cn` にそろえると決まった(2026-11-20)。部品の読み込み先を直し、`cn` パッケージを外した
- 今後 shadcn で部品を足す時も、読み込み先を直す必要がある

## spec に書いていないことで決めたこと

- 最初の元手は、設定の画面(T7)ができるまで SPEC-005 の既定値 10,000円 で固定。T7 で設定の値につなぐ
- 年次の表の税金、運用中、貯金は「お試し期間あり・貯金あり」の値にし、合計は3つの条件を並べた(ワイヤーフレームのとおり)。表の上にそう書いた
- グラフの代わりの文字: グラフに、3つの条件の終わりの合計を読み上げる名前を付けた。数字の全体は年次の表で読める
- 税金 ON の時、「年末に線が少し下がるのは、税金を引いているため」と添えた。初心者が線の下がりを損失と読まないため
- スマホの幅では「表は横に動かせます」と添えた
- shadcn のスイッチは、OS がライトモードだとつまみの色が変わる作りだった。このアプリは常に暗い色なので、つまみの色を固定した

## AI が間違えた点と学び

| 間違えた点 | どう分かったか | 次からどうするか |
|---|---|---|
| components.json の書き方で shadcn が cn をどう扱うかを確かめずに、人間に部品の追加を頼んだ。さらに `cn` パッケージを確かめる前に「無関係」と言った | 追加された部品とパッケージの中身を見て | 道具が書き換える設定は、先に道具の中身か試しの実行で確かめる。確かめる前に断定しない |
| 数字のはみ出しのテストを、幅 390px と 1440px だけで作った。どちらも数字が収まる幅で、折り返しを外しても通った | わざと壊して確かめた時 | 「はみ出さない」は、一番狭くなる幅を探してから確かめる(カード3枚が横に並ぶ 900px を足した) |
| 幅を変えた直後に、はみ出しを1回だけ測った。グラフが前の幅のまま残っていて、続けて動かすと失敗することがあった | 全部のテストを流した時に1回失敗した | 描き直しを待つ必要がある所は、待ってから(poll で)測る |
| わざと壊したあと、元に戻すつもりで対話式のコマンド(git checkout -p)を書いてしまい、入力待ちで止まった | コマンドが返ってこなかった | 止めて git status で何も消えていないことを確かめた。壊した箇所(折り返し)は手で戻し、全部のテストを流し直した。壊して確かめる時は、元のファイルの写しから戻す手順を先に決めておく |
