## 出力

- `/simulator` の画面: 条件(4つのスライダーと税金のスイッチ)、3つの条件の終わりの合計、資産の推移のグラフ(Recharts)、年次の表
- `src/components/simulator/simulator-model.ts`: スライダーの刻みの数から入力を作る処理、画面の言葉、円の表し方、グラフのデータ(単体テスト 19件)
- `e2e/simulator.spec.ts`: 画面のテスト 14件(デスクトップ 1440px とスマホ 390px の両方で動く。表の横スクロールはスマホだけ)
- shadcn/ui の slider、switch、card(人間が Mac で追加。commit 89102b5)

## shadcn の部品の cn について

人間が `npx shadcn@latest add` で部品を足したところ、部品が `cn`(クラス名をつなぐ関数)を npm の `cn` パッケージから読む形になり、`cn` パッケージが依存に入った。

- 最初、人間に「無関係なパッケージ」と伝えたが、中身を確かめると shadcn の作者が出している公式のパッケージ(clsx と tailwind-merge の代わり)だった。言い方を訂正する
- shadcn 4.23 の中身を読むと、部品を足す時に clsx と tailwind-merge を `cn` パッケージに書き換える処理があった。components.json の設定で止める方法は見つけられなかった
- 2つの cn のどちらにそろえるかを人間に聞き、自分の `@/components/ui/cn` にそろえると決まった(2026-11-20)。部品の読み込み先を直し、`cn` パッケージを外した
- 今後 shadcn で部品を足す時も、読み込み先を直す必要がある

## 確かめたこと(証拠)

- 単体テスト 168件、型チェック、lint、画面のテスト 85件(ほかに、スマホだけのテストをデスクトップで飛ばした1件)が成功(レビューの修正のあと)(AI の作業環境。Chrome は手元のものを PW_CHROME_PATH で指定)
- 既定値の3つの合計(46,031円、52,806円、62,139円)は、T5 で Python の Decimal と比べた値を1円未満で四捨五入したものと一致
- 幅 1440px と 390px のスクリーンショットを AI が見て、崩れがないことを確かめた(AI の作業環境の開発サーバー。人間の Mac ではまだ見ていない)
- わざと壊して、テストが落ちることを確かめた

| 壊し方 | 結果 |
|---|---|
| 「お試しなし」の線を実線にする | AC-005-07 のテストが失敗 |

| 合計の数字の折り返し(overflow-wrap)を外す | 最初は通ってしまった(下を参照)。幅 900px を足したあとは失敗 |

## spec に書いていないことで決めたこと

- 最初の元手は、設定の画面(T7)ができるまで SPEC-005 の既定値 10,000円 で固定。T7 で設定の値につなぐ
- 年次の表の税金、運用中、貯金は「お試し期間あり・貯金あり」の値にし、合計は3つの条件を並べた(ワイヤーフレームのとおり)。表の上にそう書いた
- グラフの代わりの文字: グラフに、3つの条件の終わりの合計を読み上げる名前を付けた。数字の全体は年次の表で読める
- 税金 ON の時、「年末に、その年の利益から税金を引いています」と添えた。初心者が年末の線の下がりを損失と読まないため(言い方はレビュー 7 で直した)
- plan に「shadcn の Chart コンポーネントが Recharts 3.11 に対応しているか T6 で確かめる」とあったが、Chart コンポーネントは使わず Recharts を直接使った。そのため対応は確かめていない
- `card.tsx` は人間が追加した部品で、この画面では使っていない(レビュー 10)。成績(T11)などのカードで使う見込みなので残した
- スマホの幅では「表は横に動かせます」と添えた
- shadcn のスイッチは、OS がライトモードだとつまみの色が変わる作りだった。このアプリは常に暗い色なので、つまみの色を固定した

## レビュー(reviewer)と対応

reviewer の指摘は10件(高 0、中 5、低 5)。どれも spec を変えずに直せるので、人間の指示(2026-11-19)により AI が推奨どおりに直した。直したあと、それぞれわざと壊してテストが失敗することを確かめた。

| 番号 | 重要度 | 指摘(要点) | 対応 |
|---|---|---|---|
| 1 | 中 | お試し期間と貯金の割合のスライダーが動かなくなっても、画面のテストがすべて通る | 4つのスライダーそれぞれで、矢印キーで1刻み動かし、値の言葉、3つの合計、グラフが変わり、戻せることを確かめるテストにした。2つのスライダーを止めると、それぞれのテストが失敗する |
| 2 | 中 | 税金のスイッチのテストがグラフを見ていない | グラフの線が描き直されることを足した |
| 3 | 中 | 上限の値で、年次の表の数字や「1年目」が折り返される | 表のセルを折り返さないようにした(数が大きい時は枠の中で横に動く)。上限のテスト(税金 OFF にして一番大きな数にした)で、表のセルが1行で出ることを確かめる。折り返しを戻すと失敗する |
| 4 | 中 | 全体の枠線の色の規則が `@layer` の外にあり、`border-primary` などに勝っていた。色の比のテストが画面にない組み合わせを見ていた | 規則を `@layer base` に移した。スライダーのつまみの縁が primary の色で出ることを画面のテストで確かめる。規則を外に戻すと失敗する |
| 5 | 中 | 税金のスイッチの次の Tab が、グラフの中の4つの層に止まる | 原因を調べた。Recharts が React のポータルで `<g>` の層を作り、React がポータルの入れ物にフォーカスのイベントを登録し、Chrome がフォーカスのイベントを持つ SVG の要素を Tab の止まり先にしていた(小さな SVG で、focus のイベントを付けると止まり、keydown や click では止まらないことを確かめた)。層に `tabindex="-1"` を付けて Tab の順番から外した。スイッチの次の Tab が表に移ることを画面のテストで確かめる。外すと失敗する。Chrome 以外のブラウザでは確かめていない |
| 6 | 低 | 外側の section とスクロールする div が同じ名前で、読み上げで2回出る | スクロールする div の名前を「年次の表(横に動かせます)」にした |
| 7 | 低 | 「線が少し下がる」は、利益率 0% や 1% の時に合わない | 「年末に、その年の利益から税金を引いています」にした |
| 8 | 低 | AC-005-04 で、3年目の合計の3列のうち2つだけを、列を決めずに見ている | 列ごとに3つの値を比べるようにした |
| 9 | 低 | スイッチが小さい(32 x 18.4px) | 「税金(20.315%)を引く」の文字の行(高さ 44px)全体を押せる範囲にした。文字を押して切り替わることを画面のテストで確かめる |
| 10 | 低 | `card.tsx` がどこからも使われていない | 残した。理由は上の「決めたこと」 |

## AI が間違えた点と学び

| 間違えた点 | どう分かったか | 次からどうするか |
|---|---|---|
| components.json の書き方で shadcn が cn をどう扱うかを確かめずに、人間に部品の追加を頼んだ。さらに `cn` パッケージを確かめる前に「無関係」と言った | 追加された部品とパッケージの中身を見て | 道具が書き換える設定は、先に道具の中身か試しの実行で確かめる。確かめる前に断定しない |
| 数字のはみ出しのテストを、幅 390px と 1440px だけで作った。どちらも数字が収まる幅で、折り返しを外しても通った | わざと壊して確かめた時 | 「はみ出さない」は、一番狭くなる幅を探してから確かめる(カード3枚が横に並ぶ 900px を足した) |
| 幅を変えた直後に、はみ出しを1回だけ測った。グラフが前の幅のまま残っていて、続けて動かすと失敗することがあった | 全部のテストを流した時に1回失敗した | 描き直しを待つ必要がある所は、待ってから(poll で)測る |
| 枠線の色のテストを足したら失敗し、最初はコードの問題だと思った。実際は開発サーバーの古いキャッシュ(.next)が前の CSS を返していた | 新しく立ち上げ直すと、正しい色が出た | CSS を直したあとに結果がおかしい時は、まずキャッシュを消して確かめる。わざと壊して確かめる時も、毎回キャッシュを消した |
| わざと壊したあと、元に戻すつもりで対話式のコマンド(git checkout -p)を書いてしまい、入力待ちで止まった | コマンドが返ってこなかった | 止めて git status で何も消えていないことを確かめた。壊した箇所(折り返し)は手で戻し、全部のテストを流し直した。壊して確かめる時は、元のファイルの写しから戻す手順を先に決めておく |
