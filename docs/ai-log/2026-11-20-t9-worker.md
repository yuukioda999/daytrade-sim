## 人間に確かめたこと

- T8 の本物での確かめ: 人間が自分のキーで「接続を確かめる」を押し、成功した(SOXL、2026-11-19 19:55 米国東部時間の足)。ADR-0005 の前提(無料のプランで全市場のデータを15分遅れで取れる)が本物で確かめられた。ADR-0005 に追記した
- ADR-0009 記録の作り方。選択肢(その日を足から作り直す、状態を少しずつ進める)を示し、人間が「作り直す」(推奨)を選んだ
- SPEC-003 定義 11(止まっていた間を取り直す)と SPEC-004(止まっていた日は行を作らない)の食い違い。人間が「取り直すのは動いた日だけ」(推奨)を選んだ。SPEC-003 に追記した
- レビューのあとに4つ(すべて推奨を採用): 同じ時刻は全銘柄の買いを先に(SPEC-003 定義 15)、OFF は足を受け取った時刻で比べる、取引量の基準の過去の日は日を始めた時に固定する(SPEC-002 決めたこと 4)、受け取った時刻のない足は「あとから処理」

## 出力

- `src/domain/trading/day-replay.ts`: その日の足を最初から順に処理して、記録を作る純粋関数(T3 の evaluateBar、T4 の enter、processBar、settleSessionEnd を使う)
- `src/domain/signal/volume-history.ts`: 過去の同じ時刻の取引量(SPEC-002 定義 4。短縮取引日で閉まっていた日は数えず、足がない日は 0)
- `src/application/worker-service.ts`: 1分ごとの処理(runTick)。今日の足を取り、今日の記録を作り直して置き換える。その日を始める時に元手と為替を保存し、過去20取引日の足を埋める。取引終了から30分で締める。前の日に締める前に止まった日を締める。様子(動いている、休み、キーがない、データを取れない、休場日の表が古い)を DB に書く
- `src/worker/main.ts` と `npm run worker`
- 保存先: 足に受け取った時刻、自動売買の ON / OFF の履歴、動いた日、練習売買の記録、ワーカーの様子
- `src/infrastructure/market-data-factory.ts`: 取得元を作る処理を、画面のサーバーとワーカーで共通にした

## 確かめたこと(証拠)

- AI の作業環境で、単体テスト 388件、型チェック、lint、画面のテストが成功(レビューの修正のあと)
- ワーカーを、テスト用の取得元と一時の DB で起動し、様子(キーがない)が DB に書かれること、Ctrl+C で止まることを確かめた。既定の DB とテスト用の取得元を組み合わせると起動しないことも確かめた
- 本物の Alpaca で、取引時間中にワーカーを動かしてはいない(AI の作業環境は Alpaca に通信できない)
- わざと壊して、テストが落ちることを確かめた

| 壊し方 | 結果 |
|---|---|
| OFF でも買う | 単体テスト2件が失敗 |
| 終わっていない足も取る | 単体テスト1件が失敗 |
| 過去20取引日の足を埋めない | 単体テスト7件が失敗 |
| 取引終了のあと30分待たない | 単体テスト1件が失敗 |
| 「あとから処理」の印の時間を長くする | 単体テスト1件が失敗 |
| 取引時間が終わってから初めて動いた日も記録する | 単体テスト1件が失敗 |

## spec に書いていないことで決めたこと

- ワーカーは、終わりが15分以上前の足だけを取る(足の途中の値を保存しないため。同じ足は二度と保存し直さない)。最初は「16分前まで」で考えていたが、5分足の途中の値が入るので直した
- 「あとから処理」の印: 足の始まりから30分(足の長さ 5分 + 遅れ 15分 + 余裕 10分)より後に受け取った足で起きた売買。締めるのが取引終了から40分より遅れた時の「取引終了」の売りも
- 取引時間が終わってから初めて動いた日は記録しない(取引時間中に動いていないため)
- 過去20取引日の足が足りない時は、日を始める時に Alpaca から取って埋める。取れない時も売買は止めず、30分ごとに取り直す
- 締めた日は「取り終えた日」として記録し、次の日からの取引量の基準に使う(T8 のレビュー 4)
- DB の場所は、画面のサーバーと同じく起動したフォルダから決める(ADR-0007 に追記。人間の確認待ち)

## AI が間違えた点と学び

| 間違えた点 | どう分かったか | 次からどうするか |
|---|---|---|
| 同じ時刻の複数銘柄の処理の順を、銘柄ごとにまとめた。足の始値の時点では使えないお金を使える形になっていた | reviewer の指摘 1 | 同じ時刻に起きることは、現実に起きる順(始値、足の途中、足の終わり)で並べてから処理を書く |
| ワーカーが足を「16分前まで」取る形で考え、終わっていない5分足の途中の値を保存するところだった | テストを書く前に、足の始まりと終わりと遅れを時刻で並べて考え直した | 時間でデータを区切る時は、データの始まりだけでなく終わりの時刻で考える |
| テストで、取引時間が終わったあとに初めて動かす形で1日目を作り、自分で決めた「その日は記録しない」に当たって失敗した | テストが失敗した | テストの前提を作る時は、自分が足した決まりに当たらないかを確かめる |
| 締める前に止まった日の「取引終了」の売りに、最初は印が付かなかった(足は時間どおり届いていたため) | テストが失敗した | 「あとから処理」は、足が届いた時刻だけでなく、その売買を決めた時刻で考える |

## 確かめていないこと

- 本物の Alpaca で、取引時間中にワーカーを動かした時のふるまい(人間に頼む)
- 画面のサーバーとワーカーが同時に同じ DB に書く時のふるまい(WAL と待つ時間は設定してある)
- 何日も止めたあとの、過去20取引日の足の埋め方の速さ
