## 指示

T9 のマージのあと、人間が「お願いします」と T10 の開始を指示した。実装、レビュー、指摘の修正までを続けて行い、マージの前に人間に声をかける(2026-11-19 の人間の指示)。AC-007-18(過去データで試す表示)は T11 に回す(plan のとおり)。

## 人間に確かめたこと

- 今日の記録がない時(日本の昼間、週末、休場日)に何を出すか(reviewer の指摘 7)。選択肢(最後に記録した日を出す、今日の分だけ出す)を示し、人間が「最後に記録した日を出す」(推奨)を選んだ。SPEC-007 に AC-007-21 と決めたこと 2 を足した

## 出力

- `src/application/dashboard-service.ts`: 保存している足と記録から、画面に出す値を作る(T9 の computeDay で、その日を作り直した結果を使う。外とは通信しない)。表示する日は、今日の記録があれば今日、なければ一番新しい記録の日
- `src/app/api/dashboard/route.ts`: 読み込みだけの API(このパソコンの画面からだけ。T9 のセキュリティレビュー)
- `src/components/dashboard/`: ダッシュボード(監視リスト、lightweight-charts の価格チャート、チャートの要点の文字、買いサインのカード、ワーカーの様子、今日のお金の状況、損失の上限の警告、今持っている株)、自動売買の記録の画面(ルール、今持っている株、売買の記録)、表示の形を決める純粋関数(`dashboard-model.ts`)。1分ごとに API を読み直す(SPEC-007 決めたこと 1)
- 画面のテスト: 決めた記録を入れた DB(`src/testing/seed-dashboard-db.ts`)と、止まった時計(`DAYTRADE_FAKE_NOW`。テスト用の取得元と既定でない DB の時だけ受け付ける)で動く2つ目のサーバー。DB にない状態(損失の上限、止まっている、データを取れない、0件)は、本物の API の応答の一部を書き換えて確かめる
- テスト用の取得元(`ScriptedSource`)を、単体テストと DB を作る処理で共通にした(`src/testing/scripted-market.ts`)
- README: `npm install` を `npm ci` にした(Mac で `npm install` が package-lock.json を書き換え、`git pull` が止まったため)

## spec に書いていないことで決めたこと

- 「自動売買が止まっています」と出すのは、ワーカーの最後の動きから3分を超えた時(1分ごとに動くので3回分)
- 売買の記録、今日の損益、損失の上限に達したかは、ワーカーが保存した記録から作る。足から計算し直すのは、チャート、3つの条件、持っている株の今の損益と売りの基準だけ(reviewer の指摘 2)
- 前の取引日は休場日の表で決め、その日の足を取れていなければ前日比を出さない(reviewer の指摘 4)
- 損失の上限の使用割合は、上限に達するまでは切り捨てて最大 99%、達したら 100%(reviewer の指摘 6)
- 取引量の倍率は小数2桁で切り捨てる(reviewer の指摘 12)
- 買いサインのカードは、一番新しい買いを出す。同じ時刻に複数を買った時は、まだ持っている銘柄を出す
- 監視リストで最初に選ぶ銘柄は、持っている銘柄、なければ条件が多くそろった銘柄
- 3つの条件の達成状況は、届いている最後の足で判定した値(SPEC-002 AC-002-07)
- 帰属表示は、チャートの部品が出す TradingView のロゴ(リンク)。画面の文字では部品の名前だけを書き、URL は書かない(src の中の通信先を Alpaca だけにする決まりのテストがあるため)。ロゴのリンクは押した時だけ外のサイトを開く例外として ADR-0002 に追記した(security-reviewer の指摘 2)
- 画面のテスト用の2つ目のサーバーは、ビルドの置き場を `.next-e2e-dashboard/` に分ける(`DAYTRADE_NEXT_DIST_DIR`)。Next.js がこの置き場の型の場所を `tsconfig.json` に書き足すので、その形をコミットした(テストのたびに書き換わらないように)

## 確かめたこと(証拠)

- AI の作業環境で、単体テスト 448件、型チェック、lint、画面のテスト 128件(ほかにスマホの幅だけ、デスクトップの幅だけのテストを飛ばした 18件)が成功(レビューの修正のあと。Chrome は手元のものを PW_CHROME_PATH で指定)
- reviewer の指摘 2 を直したテスト(「あとから処理」の印を保存した記録のとおりに出す)は、直す前の形(計算し直した記録を出す)に戻すと失敗することを確かめた
- テストの DB と止まった時計でサーバーを立て、デスクトップ(1440px)とスマホ(390px)の幅で両方の画面のスクリーンショットを撮って見た。最初の版では、右の欄の損益の数字と「未達」が折り返していたので、折り返さないように直した

## レビュー(reviewer、security-reviewer)と対応

reviewer の指摘は20件(高 2、中 5、低 13)、security-reviewer の指摘は4件(中 1、低 3)。reviewer の 7(spec にない動き)は人間に確かめた。ほかは人間の指示(2026-11-19)により AI が推奨どおりに直した。

## AI が間違えた点と学び

| 間違えた点 | どう分かったか | 次からどうするか |
|---|---|---|
| 持っている株の損益の手計算を 0.3186円とした(正しくは 3.186円。0.05 × 0.4248 = 0.02124 の桁を誤った) | 単体テストが失敗した。実装ではなく手計算の誤りだった | 手計算は途中の値を書いてから比べる |
| e2e の「最後にデータを受け取った時刻」を 10:17 と書いた(正しくはワーカーが最後に足を受け取った 10:15)。日付の形を 11/02 と書いた(画面は 11/2) | 画面のテストが失敗した | 時刻の期待値は、テストの DB から実際の値を出して手計算と比べてから書く |
| 同じ時刻に2つ買った時、カードに売り終わった銘柄が出た | 画面のテストが失敗した | 同じ値で並ぶ場面の選び方を、先に決めてテストに書く |
| AC-002-07(朝の高値までの残りの値幅)を出し忘れた。AC-007-11 が参照する別の spec の基準を読まなかった | reviewer の指摘 1 | 参照している受け入れ基準を開いて、表に写してから作る |
| 画面を開いた時刻でその日を計算し直し、保存した記録と食い違う形にした | reviewer の指摘 2(再現あり) | 保存したものがある値は、保存したものを読む。計算し直す値を絞る |
| 画面の文字に TradingView の URL を書いた | 通信先を Alpaca だけにする決まりの単体テストが失敗した | 外の URL を書く前に、その決まりのテストを思い出す |
