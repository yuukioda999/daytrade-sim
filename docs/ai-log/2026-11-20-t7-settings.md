## spec に書いていないことで決めたこと

- まだ保存していない時の値: 元手 10,000円、為替 150円、自動売買 ON(SPEC-006 に追記。人間の確認待ち)
- 元手と為替を初めて保存する時だけ今日から使い、2回目からは次の取引日から使う(SPEC-006 に追記。人間の確認待ち)
- 為替レートは 100 倍した整数で保存する(150.25 は 15025)。小数の誤差を持ち込まないため
- 画面に出すのはキー ID の末尾4文字。シークレットは1文字も返さない
- 設定の API を、このパソコンの画面からの呼び出しに絞った(Host が localhost、127.0.0.1、[::1] のどれか。別のサイトからの書き込みは Origin と Sec-Fetch-Site で断る。書き込みは JSON だけ)。`npm run dev` は同じネットワークの別のパソコンからも開ける形で立ち上がる(Network: と出る)ので、その対策。ADR-0006 の補強で、新しい通信先は増やしていない
- JSON として読めない本文は、エラーをログに出さずに 400 を返す。JSON.parse のエラー文には本文の先頭が入るため
- 画面のテストは本番とは別の DB ファイル(`.e2e/`、コミットしない)を使う。設定を書き換えるテストはデスクトップの幅だけで、順番に動かす(2つの幅が同時に同じ DB を書き換えないように)
- `drizzle-kit` は、開発の時だけ使う道具。`npm audit` で、drizzle-kit が使う古い esbuild に中程度の注意が4件出る(esbuild の開発サーバーの機能の問題)。このアプリは esbuild の開発サーバーを使わない。直すには drizzle-kit の古い版(0.18)に戻す必要があり、そうしていない

## AI が間違えた点と学び

| 間違えた点 | どう分かったか | 次からどうするか |
|---|---|---|
| キーがログに出ないことのテストで、JSON として読めない本文を「途中で切れた形」で作った。この形のエラー文には本文が入らないので、エラーをログに出してもテストが通った | わざと壊して確かめた時 | 漏れを確かめるテストは、漏れが起きる形の入力(エラー文に本文が入る形)で作る。先に、その入力で本当にエラー文に本文が入ることを確かめる |
| キーがないことのテストで、シークレットの末尾4文字 "0000" を探したため、元手の 10000 に引っかかって失敗した | テストが失敗した | 探す文字は、ほかの値に出てこない文字にする |
| 設定の画面で「保存」のボタンが2つになり、画面のテストがどちらか決められなかった | 画面のテストが失敗した | ボタンの名前は、画面の中で何を保存するかが分かる名前にする(読み上げでも区別できる) |
