## 指示

PR #11(T10)のマージを受けて T11 を進める。実装、レビュー、指摘の修正までを続けて行い、マージの前に人間に声をかける(2026-11-19 の人間の指示)。

## 人間に確かめたこと

- ADR-0007: DB の場所を起動したフォルダから決める今の作りで「このままでよい」(推奨)
- ADR-0010 決めること 1(どこで始め、どう見せるか): 「全部作る」(推奨。設定の画面のボタン、成績の画面の別の欄、ダッシュボードの切り替えと試した日の表示)
- ADR-0010 決めること 2(お金と試す日): 「損益を次の日に引き継ぐ」(推奨。最後に保存した元手と為替で始め、自動売買は毎日 ON、4銘柄すべての足がある日だけ)
- SPEC-004: 途中で元手を変えた時の割合は「一番新しい日の元手」で割る(推奨)
- SPEC-004: 取引の途中の日は、まとめから外す(推奨。reviewer の指摘 6)

## 出力

- `src/application/backtest-service.ts`: 過去データで試す。4銘柄の足を取り終えた日を古い順に、T9 の computeDay(mode "backtest")で処理し、損益を引き継ぐ。結果は新しい3つの表(backtest_runs、backtest_days、backtest_trades)に保存し、試すたびに置き換える
- `src/application/results-service.ts`: 成績の画面の値。毎日の記録(day_runs と trades)と試した結果を別々に作る
- `src/application/dashboard-service.ts`: 試した1日分をダッシュボードと同じ形で出す(getBacktestDashboardView)。今日の分と共通の部分を dayParts に分けた
- API: `POST /api/backtest`、`GET /api/results`、`GET /api/dashboard?backtest=YYYY-MM-DD`
- 画面: 成績の画面(まとめ、日ごとの棒グラフ、日ごとの表、試した結果の欄)、設定の画面の「過去データで試す」、ダッシュボードの「今日の市場 / 過去データで試す」の切り替えと、試した日を大きく出す表示
- 米国東部時間の変換を速くした(ずれを UTC の1時間ごとに覚える。toEastern をずれの足し算で計算する)。Intl で分解した値と、2025 年から 2027 年の15分ごとの全部の時刻で同じことをテストで確かめた
- 画面のテストの DB に、過去データで試した結果を足した(2026-09-02 から 10-30 の41日。10-01 に SOXL の損切り)

## 確かめたこと(証拠)

- 1年分(251取引日、売買のない作り物の足)を試す時間: 速くする前は 41日分で約5.9秒、速くしたあとは 251日分で約4.1秒(AI の作業環境)。時間の大半が米国東部時間の変換(Intl)だったことを CPU のプロファイルで確かめてから直した
- テストの DB で、成績の画面と試した日のダッシュボードのスクリーンショットを撮って見た。1日だけの棒グラフで軸に 0円が入らず、棒の向きが分からなかったので、軸に必ず 0円を入れるようにした。試した日を見ている時に、毎日の記録の画面へのリンク(「自動売買の記録を見る」「詳細」)が出ていたので、出さないようにした
- AI の作業環境で、単体テスト 477件、型チェック、lint、画面のテスト 148件(ほかに幅の違いで飛ばした 18件)が成功(レビューの修正のあと)
- 引き継いだ損益で買う量が変わるテストは、引き継ぎを 0 に戻すと失敗することを確かめた

## spec に書いていないことで決めたこと

- 試す時の元手と為替は「設定の画面で最後に保存した値」(次の取引日から使う値を含む)。今日の値ではなく、入れたばかりの値で試せるようにするため(ADR-0010 の「試し始める時の設定」の読み方)
- 試した日を見ているダッシュボードでは、自動売買のプロセスの様子の欄を出さない
- 成績の画面の試した結果の表の日付から、ダッシュボードのその日へ移れる(AC-007-18 の入り口)

## AI が間違えた点と学び

| 間違えた点 | どう分かったか | 次からどうするか |
|---|---|---|
| 試す処理を最初に作った時、41日分で約6秒かかった | 画面のテストが時間切れになり、測って分かった | 何万回も呼ぶ処理は、作ったらすぐ時間を測る |
| 引き継ぎのテストを足すつもりで、文字の置き換えが当たらず足されていなかった | テストの件数が増えていないことと、引き継ぎを壊してもテストが通ったことで分かった | テストを足したら、壊すと失敗することを毎回確かめる |
| 損益の引き継ぎのテストが、引き継ぎを無視しても通る形だった | reviewer の指摘 4 | 値が「保存されたこと」ではなく「結果を変えること」を確かめる |
