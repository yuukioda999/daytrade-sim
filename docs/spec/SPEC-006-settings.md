# SPEC-006: 設定とデータの接続

- 状態: 承認済み(2026-11-19)
- 日付: 2026-11-19
- 関連する ADR: ADR-0003、ADR-0005、ADR-0006

## 目的

自動売買の ON / OFF、市場データの接続、過去データの取得、元手と為替を設定する。

## 範囲

- 含むもの: 上の4つの設定
- 含まないもの: 通知(第1弾ではやらない)

## 受け入れ基準

### 自動売買

| ID | 前提 | 操作またはできごと | 期待する結果 |
|---|---|---|---|
| AC-006-01 | 自動売買が ON | OFF にする | 次の足から新しく買わない。持っている株の売りの判定は続ける |
| AC-006-02 | 設定画面 | 表示する | 1回の買いの予算(元手の50%)と、今日の損失の上限(元手の10%)を、変えられない値として出す |

### 市場データの接続

| ID | 前提 | 操作またはできごと | 期待する結果 |
|---|---|---|---|
| AC-006-03 | キーが未設定 | キー ID とシークレットを入れて保存する | サーバー側の SQLite に保存する。画面には「設定済み」と末尾4文字だけを出す |
| AC-006-04 | キーが設定済み | 設定を読み込む API を呼ぶ | 応答にキーの全文が含まれない |
| AC-006-05 | キーが設定済み | 「接続を確かめる」を押す | Alpaca から SOXL の最新の足を1本取り、成功か失敗かを出す。失敗の時もキーを画面とログに出さない |
| AC-006-06 | キーが設定済み | 削除する | キーを消し、画面は「未設定」になる。自動売買はデータを取れないので止まり、その理由を出す |
| AC-006-07 | どの操作でも | 外部と通信する | 通信先は Alpaca のデータ API のホストだけ |
| AC-006-08 | キーが空、または形式が違う | 保存する | 保存せず、どこが違うかを出す |

### 過去データの取得

| ID | 前提 | 操作またはできごと | 期待する結果 |
|---|---|---|---|
| AC-006-09 | キーが設定済み | 期間を選んで取得する | Alpaca から4銘柄の足を取り、保存する。進み具合を出す |
| AC-006-10 | 一部の期間を取得済み | 重なる期間を取得する | 同じ足を二重に保存しない |
| AC-006-11 | 取得の途中で失敗 | 失敗する | それまでの分は残し、失敗した期間を出す。もう一度取得できる |
| AC-006-12 | 過去データがある | 「過去データで試す」を実行する | SPEC-002 と SPEC-003 のルールで試し、結果を毎日ためた記録とは別に保存する(SPEC-004) |

### 元手と為替

| ID | 前提 | 操作またはできごと | 期待する結果 |
|---|---|---|---|
| AC-006-13 | 設定画面 | 元手を入れる | 1,000円から 10,000,000円の整数だけを受け付ける |
| AC-006-14 | 設定画面 | 為替レートを入れる | 50 から 300 までの、小数2桁までの数だけを受け付ける |
| AC-006-15 | 記録がある | 元手か為替を変える | 次の取引日から反映する。過去の記録は計算し直さない |

## 決めたこと(2026-11-19、推奨をすべて採用)

1. 過去データの入手方法。採用は「Alpaca から期間を指定して取得する」(ADR-0005 で、過去データと毎日のデータを1つの接続で取れることを選定の理由にした。ファイルの読み込みがなければ、ファイルの中身の検査も要らない)。ワイヤーフレームは「ファイルを選ぶ」になっていたので、こちらに直す
2. 1回の買いの予算と今日の損失の上限を、設定で変えられるようにするか。採用は「変えられない値として表示だけする」(決まっていない機能を足さない。テストする組み合わせが増えない)。ワイヤーフレームは選べる形になっていたので、表示だけに直す
3. 過去データで試せる期間の上限。採用は「最大1年」(取得の量と時間を抑える。4銘柄の5分足で1年は約 7.5 万本の見込み、未確認)

## 決めたこと(2026-11-20 追記)

4. AC-006-08 の「形式が違う」の決め方。人間が「ゆるく確かめる」を選んだ。キー ID とシークレットのそれぞれについて、前後の空白を取り、英字と数字だけの 16 から 64 文字なら受け付ける。空白、改行、記号の混ざった貼り付けミスを防ぐ。Alpaca はキーの長さや先頭の文字を決まりとして示していない(先頭の PK は目印とされている)ため、見本の形には合わせない。正しいキーかどうかは「接続を確かめる」(AC-006-05)で分かる

## T7 で決めたこと(2026-11-20)

5. まだ一度も保存していない時の値は、元手 10,000円、為替レート 150円、自動売買 ON(ワイヤーフレームと SPEC-003 の例の値。AI の推奨。PR #7 で人間が確認する)
6. AC-006-15 の前提「記録がある」の扱い(T7 のレビュー 1 を受けて、2026-11-20 に人間が推奨を採用)。自動売買(T9)がその日を始める時に、その日に使う元手と為替(まだ保存していなければ既定の値)を保存する。保存した値が1つでもあれば、そのあとの変更はいつも次の取引日から使う。自動売買がまだ一度も日を始めておらず、利用者も保存していない時だけ、初めての保存を今日から使う。こうすると、既定の値で動いている日の途中で、初めての保存によって前提が変わることがない
